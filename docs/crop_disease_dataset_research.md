# Public crop disease data for weather risk validation

Research checked: 23 October 2026. This comparison is based on the official source pages and files that could be accessed during this review. A landing page that lists a file is not treated as evidence that the file was downloaded or its records inspected.

## Recommendation

The Dryad dataset is the strongest of these three candidates for a first weather association validation: its public description reports 4,339 plant–disease populations, defines infection prevalence, and explicitly provides linked historical and contemporaneous climate/weather covariates. Its records come from a systematic literature review, however, so they are study/population summaries with approximate named locations and study-period timing—not plot-level, daily field observations. It is not suitable for validating exact daily alerts in a particular Indian district without checking the source studies and spatial/time alignment.

The Dryad binary could not be downloaded in this environment: the official file URL returned HTTP 403. Therefore I have not inspected its CSV cells, measured missingness, confirmed the actual row count or field values, or verified that all 4,339 described populations are in the downloadable files. **No dataset file was created or downloaded.** The Dryad page's 972.42 KB ZIP listing and README description are verified page metadata, not a verified local file.

## Source-level findings and limits

### ICAR-IIRR

The official database page supports only the broad description: district-level distribution and intensity of rice diseases over three decades. It does not expose a downloadable table in its readable content. The institute directory also lists the POS Data Portal, but the directory page does not say whether the portal is open to anonymous users or what fields it contains. I could not verify disease names, disease metric units, sampling dates, missing districts/years, duplicate rows, weather variables, or licence. Treat ICAR as a promising India/rice source to revisit if the POS portal becomes publicly queryable; do not treat the page description as a usable data file.

### Dryad

The Dryad landing page and its embedded README describe two CSVs: literature-review plant disease survey records and associated climate/weather records, joined with an observation identifier. The stated numerator/denominator allow prevalence to be calculated, and the climate file contains historic and contemporaneous covariates. This is the closest conceptual fit to weather-risk validation among the three because the study assembled disease prevalence and climate together.

The dataset is not a set of uniformly collected field visits. It combines records abstracted from published studies; study locations are described as approximate named places and timing as the number of months and starting month. Different studies may therefore differ in disease assessment, sampling frame, and resolution. The downloadable workbook/archive could not be retrieved (HTTP 403), so actual column spelling, file row counts, per-field missingness, duplicates, disease/crop coverage, units, and any further caveats inside the files remain unverified. Do not infer missing records are healthy. Because weather covariates are already supplied, any future matching should preserve the supplied `obs` key and inspect the source study timing and location before comparing against CropAI weather data; do not substitute a daily weather value for a study-period summary.

### Bhuvan

The public portal page supports filters for State, District, Village, Crop, Pest, Severity, Source, and Date/Period, so it appears designed around report records rather than only images. The official [Bhuvan user handbook](https://bhuvan-app1.nrsc.gov.in/2dresources/documents/1_Bhuvan_User_Handbook.pdf), section 7.4, describes visualization of reported incidents with basic information and says uploads include pest/disease information and photographs. The handbook screenshot's popup fields include place, crop, pest, severity, and source. Neither the page nor handbook establishes an exportable public history, measurement units for severity, exact observation dates, completeness, or a reuse licence. The portal's upload endpoint redirected to CAS login; that is only evidence about uploading, not proof that viewing reports requires login. Without actual public records, weather joinability and completeness remain unknown.

## Candidate selection for this project

**Best available candidate from these three: Dryad, with a scope limitation.** Its official description explicitly connects measured prevalence, study-period information, location descriptions, and historical/current weather variables. It can support an initial retrospective analysis of broad study/population-scale weather associations if the archive can be retrieved and reviewed. It cannot, from the information verified here, validate alert timing against daily local field outcomes or establish performance for Indian rice/chickpea specifically. ICAR may have more relevant district-level Indian rice records, but public access to the underlying records was not established. Bhuvan may contain localized reports, but publicly accessible historical records and terms were not established.

### What this means for weather matching

The Indian sources that clearly describe field observations have not exposed the underlying rows in a public, inspectable file during this review. The sources with public images or summary tables lack the date/location/outcome structure required for alert validation. Without verified observation dates and locations, pairing disease outcomes with the project's historical weather would be guesswork. Do not convert an article's annual/seasonal mean into daily disease labels or treat unreported disease as healthy.

Government weather products are accessible separately: the [National Water Data Portal's Daily IMD Rainfall dataset](https://nwdp.nwic.gov.in/dataset/rainfall-daily-imd) exposes district-wise daily rainfall resources, and the [IMD gridded data interface](https://imdweb.lwcc.in/) provides rainfall and temperature archives. These are weather inputs, not disease labels, so they cannot fill the outcome-data gap.

### Project recommendation

There is no dataset from this search I can responsibly recommend as a verified historical validation set. The most practical alternative is prospective, structured field scouting for one crop and disease that matches CropAI's target: record the actual observation date, crop and disease, village/district and GPS when consented, crop stage, scouting effort, and a defined incidence/severity measure. Explicitly record “not observed” only after a real documented survey. After enough real observations have been collected, match them to the existing historical or current weather at the date and location resolution the observations support. This yields traceable alert-validation data without inventing past outcomes.
